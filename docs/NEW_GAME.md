# Shipping a new game — the checklist

Every cross-file fact a new game must touch, learned by shipping `lesen`
(2026-07): each item below failed one at a time back then and was found by
re-running the suite. Work through it top to bottom; `rechnungen`, `tippen`
and `vokabeln` will hit exactly these mines.

Read first: `docs/SPEC.md` §7 (adaptive engine), §8 (motivation/stars/
trophies), §9.2 (cookie budget), and the game's own § section. The reference
implementations are `games/einmaleins/` (keypad input, tempo ladder) and
`games/lesen/` (choice input, data-driven content).

## 0. Branch hygiene

`gh pr list --state merged --limit 5` — is the branch you are on already
merged? Branch fresh from `origin/main`. (CLAUDE.md, "a merged PR ends its
branch".)

## 1. The files a game is made of

Copy-adapt from einmaleins/lesen; keep the element ids (`#pick-overlay`,
`#journey`, `#question`, `#feedback`, `#answers`, `#sum-overlay`, `#sum-ok`,
`#pickchip`) — the CSS, the drivers and several tests key on them.

- `games/<name>/index.html` — page shell: empty `<header class="topbar"
  id="topbar">` and NOTHING else in the bar (tests/topbar.test.js), picker
  overlay, summary overlay with exactly ONE button, importmap (regenerated by
  the version tool, see §4).
- `games/<name>/<name>.js` — controller. Mirror the einmaleins round flow:
  picker → `startRound` (createSession) → ask/submit → aid (§8.1: the way out
  is the right answer, no timer, no "Verstanden") → `endRound` (persist
  FIRST, then the 700ms celebration timer — the leave guard trusts
  `roundOver` to mean "cookie written").
- `games/<name>/logic.js` — pure, unit-tested. Star helpers (`starsFor`,
  goals, digit-string codecs) are **duplicated per game, with a parity test
  against einmaleins'** (see tests/lesen.test.js) — never imported across
  games. `maxPoints(content)` computes what the game can pay.
- `games/<name>/picker.js` — copy of the picker; tiles, walk-then-open.
- `games/<name>/i18n.js` — de+en in one file.
- `games/<name>/content.js` (if data-driven) — **append-only** when item
  order feeds a box digit string; say so in the header comment. Authoring
  rules belong in a content test (sizes, uniqueness, emoji rules — see
  tests/lesen-content.test.js).

Free machinery — use, don't rebuild: `adaptive.js` (Leitner session),
`journey.js` (themes: village/mountain/forest/meadow), `overlay.js`,
`chrome.js`, `leaveguard.js`, `trophycard.js` + `showcase.js`, `confetti.js`,
`audio.js`, `levelfox.js`.

## 2. The PLAYABLE flip and everything pinned to it

Flip and page replacement in **one commit** — `stub.js` throws on a stub page
for a PLAYABLE game.

- [ ] `assets/js/rewards.js`: add to `PLAYABLE`; set `MAX_POINTS[game]` to
  the number **computed from the real tiles** (`ladderFor` throws below 12);
  update the "guesses" comment. `TROPHIES[game]` already exists for all five.
- [ ] `tests/map.test.js`: the `PLAYABLE` deepEqual pin and the
  `isPlayable(...)` asserts. **The map SVG paints playable regions after
  fogged ones** — check the new region's `<a>` position in `index.html`, a
  fog bank painted later washes out its label.
- [ ] `tests/rewards.test.js`: the `trophyCount`/`nextTrophyInfo` example
  numbers are pinned to concrete ladders — a changed `MAX_POINTS` moves
  them. Add the game's balance twin (tiles sum to `MAX_POINTS`, twelfth
  trophy reachable, first trophy in one sitting).
- [ ] `tests/topbar.test.js`: nothing to do — the stub scan derives from
  `PLAYABLE` since lesen shipped.
- [ ] `assets/js/map.js` unfogs the region automatically via `isPlayable`.

## 3. i18n

- [ ] Every UI string in BOTH `games/<name>/i18n.js` languages; shared
  strings in both `assets/i18n/*.js`.
- [ ] `tests/i18n.test.js`: add the game's dict to `gameDicts` **and** the
  parity test. Forgetting `gameDicts` fails every `t("...")` the game makes.
- [ ] Keys built at runtime (`` t(`prefix${k}`) ``) are invisible to both
  i18n scans — write your own liveness test, both directions (the
  `lesenPack<Key>` pattern in tests/lesen-content.test.js).
- [ ] `parentsOtherGames` (both languages) counts the unbuilt games — it
  just went down by one.
- [ ] Icons never inside `[data-i18n]` elements (`translateDOM` overwrites
  textContent).

## 4. Cookie, cache, deploy

- [ ] Cookie section per §9.2; add a budget test (maxed section small, and
  everything-maxed-together `< BUDGET` — see "cookie budget" in
  tests/lesen.test.js).
- [ ] `node tools/version-assets.js <n+1>` regenerates every importmap. The
  shared list carries `games/*/logic.js` and `games/*/content.js`; the
  game's other modules are picked up as page siblings. `tests/cache.test.js`
  fails on any reachable-but-unversioned module.
- [ ] Runtime assets live under `assets/` or `games/` — nothing else
  deploys.

## 5. Parents' view (§20)

Decide what the game reports and update `parents.js`/`parentstats.js` (pure
helpers + tests), or consciously skip and leave the copy honest. State with
no consumer is dead cookie bytes — don't write `tm`/`rd`-style counters
until the view renders them.

## 6. Driver and verification

- [ ] `tools/play-<name>.js` — copy the play.js/play-lesen.js shape: globals
  on an IIFE, resolver as a plain function, `SETTLE = 350` after every
  answer (the 250ms correct-wait trap), a question stamp (`dataset.q`) so a
  re-queued identical question is not misread.
- [ ] `tests/play-<name>.test.js` — run the resolver in Node against every
  `questionFor` shape. A driver that answers the wrong thing proves nothing.
- [ ] Mutation-check the new pure logic: `sh tools/mutate.sh <file>
  '<perl>' tests/<name>.test.js` — a test that cannot go red is decoration.
- [ ] Look at the page: shoot.mjs at 360×640 AND 390×844, firefox-shot.sh,
  `--reduced-motion` (any timed/animated mechanic must survive it —
  JS-timer + CSS *transition*, never a keyframe), `--do back` mid-round
  (leave guard), the map afterwards (region unfogged, badge counts).

## 7. Docs, last

- [ ] `docs/SPEC.md`: rewrite the game's § to describe what shipped; touch
  §5/§6.2/§20/§19-milestone if they name the game.
- [ ] `CLAUDE.md`: the "fully implemented" list, the driver's paragraph, the
  `MAX_POINTS` guess note.
- [ ] Version bump is the final commit before the PR; before opening it:
  `git diff --diff-filter=D --name-only origin/main..HEAD` — an unexpected
  deletion means you are undoing someone's merge.
